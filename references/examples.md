# 示例

以下是用一个虚构项目填好的样例：把各门店日报表格汇总成周报的脚本。沿用其中的粒度和口吻，内容按实际项目替换。

## 三句话说明

> 这个项目是把各门店的日报表格汇总成周报的脚本，每周一自动生成上周汇总。
> 目前汇总和导出已经能用，但提醒天数写死为 30 天，快到期的条目经常漏报。
> 这次把提醒天数改成可在配置里设置，验收标准是设成 60 天后周报能列出 60 天内到期的条目；本阶段交付配置项和一次周报实测，做完停在你确认结果。

## 决策说明

取舍涉及新增授权、测试数据或成本时，一次给齐六要素，每项一两句话：

| 要素 | 内容 |
| --- | --- |
| 1. 背景和目标 | 周报需要提前 60 天提示到期条目。 |
| 2. 已核实的进度 | 读取配置的单元测试已通过；周报脚本 `report.py` 还没有读取新配置。 |
| 3. 卡点及影响 | 周报脚本没有测试数据，补测要改动正式台账。 |
| 4. 可选方案及各自的代价 | 方案 A：用台账的只读副本造一份测试数据，约 10 分钟，不碰正式数据。方案 B：在正式台账改一条到期日再改回，最快，但会留下修改记录。 |
| 5. 我的推荐及理由 | 选方案 A：验证效果相同，又不改正式数据。 |
| 6. 本次要你决定什么 | 是否同意用只读副本造测试数据。 |

## 任务单片段

验收历史和四行交接按下面的粒度写：

```markdown
## 验收历史
- 2026-11-25｜周报列出 60 天内到期的条目｜通过｜本地运行 `report.py`，输出含 2 条临期条目｜`a1b2c3d`
- 2026-11-25｜提醒天数可在配置里设置｜未验证｜还没有带配置文件的运行环境｜

## 交接
- 已完成：配置读取和周报逻辑已改，改动在本地分支，未推送。
- 验证结果：单元测试 3 项通过；周报实测结果见上方验收历史。
- 卡点：推送到远程仓库需要你授权。
- 下次第一步：获批后推送分支并创建 PR。
```
